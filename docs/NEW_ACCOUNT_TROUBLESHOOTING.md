# 新登录微信账号：账号误选与图片密钥故障排查

这份文档记录“同一台 Windows 电脑切换或新登录另一个微信账号”时最容易遇到的两类问题。文档、日志和测试都不得写入真实 `wxid`、数据库密钥、图片密钥或朋友圈内容。

## 快速判断

先保持目标微信账号在线，进入自己的朋友圈并滚动几条，让 `sns.db` 或其 WAL 确实产生新写入，然后运行：

```powershell
.\run.bat archive --until "目标截止日期" --dry-run
```

开始正式归档前至少确认：

1. 终端显示的账号目录属于当前登录账号。
2. 缓存最早/最晚时间与刚刚滚动到的范围相符。
3. 新增条数合理；不要因为刚进入朋友圈附带了几条最新缓存，就误用 `--until latest`。
4. 图片密钥已经通过本地 V2 模板验真；日志中不得打印密钥原文。

任何一项不符都应先停止，不要生成或继续追加正式 PDF。

## 问题一：新账号登录后却识别成旧账号

### 典型表现

- 预检查显示的是上一个账号的历史日期或昵称。
- 当前账号刚加载的朋友圈没有出现在新增记录里。
- 电脑的微信数据根目录下同时存在多个 `wxid_*` 目录。

### 根因

旧实现发现多个账号时按 `sns.db` 文件大小选择。长期使用的旧账号往往数据库更大，即使当前登录的是新账号，也可能被错误选中。

### 当前修复

账号候选现在按以下顺序排序：

1. `sns.db`、`sns.db-wal`、`sns.db-shm` 中最近的写入时间。
2. 写入时间相同时，再比较主数据库大小。

检测到多个账号且未显式指定账号时，终端会输出所选账号目录和最近写入时间。对应回归测试位于 `tests/test_account_discovery.py`。

### 仍然选错时

把 `config/config.json` 中的 `wechat_data_root` 指向当前账号的精确 `wxid_*` 目录，而不是包含多个账号的上级目录：

```json
{
  "wechat_data_root": "D:\\WeChatData\\xwechat_files\\wxid_example",
  "account": "wxid_example"
}
```

配置文件仅保存在本机，不要提交到 Git。切换客户或账号时，必须使用独立的 `--state` 和 `--output-root`，或者在确认最终 PDF 已交付后清理上一账号的私有运行数据。

## 问题二：文字能读到，但图片密钥失败或图片全部缺失

### 典型表现

- 朋友圈文字和日期能解析，但 PDF 没有图片。
- 日志提示没有找到 V2 图片模板，或无法取得已验证的图片密钥。
- 账号缓存中没有旧版常见的 `*_t.dat`，但存在大量没有扩展名的 SNS 文件。

### 根因

部分新版 Windows 微信把朋友圈 V2 图片缓存保存为：

```text
cache\<年月>\Sns\Img\<分片目录>\<无扩展名哈希文件>
```

旧扫描器只寻找 `*_t.dat`，因此即使本地已经有图片，也没有模板可用于验证从微信进程取得的 AES 图片密钥。

### 当前修复

`image_key_resolver.py` 会同时扫描：

- 旧版 `*_t.dat` 图片模板。
- `cache/<年月>/Sns/Img/<分片>/<无扩展名文件>`。

候选文件仍须满足最小长度，并在读取时验证 V2 魔数 `07 08 56 32 08 07`，不是把所有无扩展名文件都当图片。扫描数量有上限，并优先选择最近修改的文件。对应回归测试位于 `tests/test_image_key_discovery.py`。

### 排查顺序

1. 在当前账号朋友圈中实际加载至少一批带图片的动态。
2. 确认账号目录选择正确；错误账号的图片模板不能用于验证当前账号的密钥。
3. 查看日志中的 V2 模板数量和扫描文件数，不要查看或复制密钥本身。
4. 如果模板数为 0，检查新版缓存路径是否再次变化，并从 `scan_v2_templates()` 的路径发现逻辑开始排查。
5. 修复后先运行完整单元测试，再用小日期范围 `--dry-run` 和试导验证。

## 回归验证

```powershell
.\runtime\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

至少应覆盖：

- 小但最近写入的新账号优先于大但陈旧的旧账号。
- 活跃写入只存在于 `sns.db-wal` 时仍能选中正确账号。
- 显式 `account` 配置优先于自动排序。
- 无扩展名 SNS V2 图片可作为密钥验真模板。

## 给维护者的处理原则

- 先确认账号，再获取和保存密钥；不要用“能解密”反推账号一定正确。
- 先 `--dry-run`，确认日期范围和新增数量，再写正式 PDF。
- 不在终端、Issue、测试夹具或提交记录中暴露任何真实密钥、真实 `wxid` 或朋友圈内容。
- 新微信版本出现兼容问题时，优先补充最小回归测试和这份文档，再修改发现逻辑。
