# wxMoments：Windows 微信朋友圈 PDF 归档工具

wxMoments 从 Windows 版微信已经写入本机的朋友圈缓存中，导出自己的朋友圈文字、完整比例图片、位置、链接、视频封面以及已缓存的点赞和评论。普通用户完成微信内的历史加载后，可以用一条命令持续增量归档，不需要 AI 参与。

> 正式支持范围仅为 **Windows 10/11 64 位**。工具依赖 Windows 版微信的本地数据结构、进程和密钥获取方式；macOS、Linux、手机微信和网页版微信不受支持。

## 当前状态

下列归档能力已经集成到工具中：

- `run.bat archive --until ...` 一键扫描、解密、导出和校验。
- 保存断点，并从上次最后一秒重新扫描；按动态 ID 哈希去重，不会漏掉同一秒的多条动态。
- 始终按时间从旧到新写入。
- 当前卷达到目标大小后自动新开卷；默认目标 45 MiB、硬上限 50 MiB。
- 分卷只发生在完整动态之间，不会把一条动态拆给两个卷。
- 正式 PDF 先写临时文件，重新打开并校验清单、页数和首尾页面后，再原子替换。
- 每卷记录首尾时间、动态数、页数、字节数和 SHA-256。
- 同一批缓存重复执行是幂等的：没有新动态时不会重写 PDF。

它仍然不是“从腾讯服务器一键下载全部历史”的工具，也不会自动控制微信滚动。完整性取决于电脑版微信实际缓存过的内容。

## 能导出什么

| 内容 | PDF 中的处理方式 |
| --- | --- |
| 动态文字、作者、发布时间 | 导出，正式归档固定按旧到新排列 |
| 一张图、九宫格、长图、竖图 | 使用本机可用的较清晰缓存，按完整比例显示，不用裁切填充，不会只显示半张 |
| 原图文件夹 | 正式归档默认不另存，避免与 PDF 重复占用空间 |
| 定位 | 数据库有定位字段时显示 |
| 点赞、评论 | 默认启用；仅能导出本机已经缓存的数据 |
| 评论表情、贴图 | 本机存在资源时显示；缺失资源无法恢复 |
| 普通分享链接 | 显示标题和 URL；有可用封面时显示封面 |
| 音乐分享 | 显示标题、URL 和可用封面 |
| 普通视频、视频号、实况照片 | PDF 显示已缓存的封面和主要文字信息 |
| 视频本体 | 不嵌入 PDF，也不单独保存；PDF 本身不能可靠承载跨阅读器可播放的视频 |

PDF 内的图片是生成时实际找到的本地缓存版本，不承诺等于微信服务器原始文件。若朋友圈界面中的缩略图明显模糊，点开图片可能促使微信缓存更清晰版本；如果当前缓存已经清晰，则不必逐张点开。无论缓存图片是什么尺寸，排版都使用 `contain` 逻辑显示完整画面，不会为了填满方格裁掉上下或左右内容。

## 使用前要求

- Windows 10 或 Windows 11，64 位。
- 已安装并能正常登录的 Windows 版微信。
- Python 3.10 或更高版本，建议 64 位。首次运行会自动建立 `runtime/.venv`。
- Microsoft Edge 或 Google Chrome。工具优先用浏览器渲染 PDF，找不到时会回退到 ReportLab。
- 足够的磁盘空间。生成过程中需要同时容纳缓存媒体、临时 PDF 和正式 PDF，建议至少预留预计归档体积的 2～3 倍。
- 首次安装依赖时可能需要联网；仓库内 wheel 匹配当前 Python 时会优先离线安装。可选的 SILK 语音转换库不属于朋友圈 PDF 的必需依赖。

所有处理默认在本机完成。不要把 `config/config.json`、`runtime/`、微信数据库、密钥、归档 PDF 或真实朋友圈内容提交到 Git 或发给他人。

## 第一次使用：从最早朋友圈开始

### 1. 获取当前项目

请获取包含本文档和新增归档功能的**当前项目完整目录**，不要直接克隆原始上游仓库。上游版本不包含这里介绍的 `archive` 断点续传、自动分卷和 PDF 校验功能。

如果拿到的是压缩包，请完整解压；然后进入包含 `README.md`、`run.bat`、`src/`、`config/` 和 `wheels/` 的项目根目录，在该目录打开 PowerShell。不要只复制 `run.bat` 或单个 Python 文件。

### 2. 登录 Windows 版微信

1. 启动电脑微信并完成登录，保持账号在线。
2. 进入“朋友圈”并打开自己的朋友圈时间线。
3. 如果工具首次自动获取数据库或图片密钥，按终端提示保持微信主界面打开。

### 3. 让微信加载历史缓存

wxMoments 读取本机缓存，不会直接向微信服务器请求完整历史。因此完整归档前，用户必须先在微信里加载目标日期范围。

1. 使用朋友圈日期导航，跳到自己最早发布朋友圈的那一天，例如 2013 年最早记录附近。
2. 从最早日期开始，按时间从旧到新向后滚动。
3. 每滚动一段就停一下，等加载提示结束，让微信把数据库和 WAL 写到磁盘。
4. 记下目前滚到的日期；可以分批归档，不必一次滚到今天。
5. 如果非常在意点赞和评论，建议打开动态详情再返回。评论和点赞只有在微信已经缓存后才能导出。
6. 普通图片不需要逐张点开；只有在缩略图明显不清晰、且希望促使微信缓存更清晰版本时才值得点开。

刚进入朋友圈时，微信可能顺带缓存几条当前最新动态。历史尚未滚到今天时，不要直接使用 `--until latest`，而应明确填写这次真正滚到的截止日期；这样不会把零散的最新缓存提前插进历史顺序。

### 4. 首次归档

假设这次已经从最早记录滚到 2016 年 1 月 19 日（包含当天）：

```powershell
.\run.bat archive --until "2016-01-19"
```

首次运行会：

1. 创建 Python 虚拟环境并安装依赖。
2. 自动定位微信账号和朋友圈数据库。
3. 获取并仅在本机保存数据库、图片解密所需信息。
4. 从本地缓存最早记录导出到指定截止日期。
5. 在 `output/archive/` 生成第一卷 PDF、清单和报告。
6. 在 `runtime/archive_state.json` 保存断点。

首次运行没有必要传 `--from`；默认就是从缓存中的最早记录开始。如果只想从某天建立一个全新归档，且还没有状态文件，可以使用：

```powershell
.\run.bat archive --from "2020-01-01" --until "2020-12-31"
```

### 5. 继续滚动并增量归档

下次继续向后滚到 2016 年 6 月 19 日后，只需要：

```powershell
.\run.bat archive --until "2016-06-19"
```

工具会从断点重新扫描边界秒、按动态 ID 去重，只把新增动态写入。不要再填写 `--from`，也不需要删除或重建以前的 PDF。

当已经从最早日期连续滚动到今天，并确认当前最新动态已加载后，可以使用：

```powershell
.\run.bat archive --until latest
```

以后每次想补充归档，登录微信、加载新动态，再运行同一条 `latest` 命令即可。

## 常用命令

### 只扫描，不写 PDF

```powershell
.\run.bat archive --until "2022-12-29" --dry-run
```

它会输出本机缓存最早/最晚时间以及预计新增条数，适合确认这次滚动是否真正写入缓存。

### 不导出点赞评论

```powershell
.\run.bat archive --until latest --keep-interactions n
```

默认是 `--keep-interactions y`。更改这个选项只影响本次新增动态；已经写入 PDF 的旧动态不会被重新抓取或重写。

### 允许联网补充媒体

```powershell
.\run.bat archive --until latest --allow-download
```

默认不联网补图，只使用本机缓存。`--allow-download` 仅在媒体 URL 仍有效时尝试补充，并不保证能取得原图。涉及隐私或长期归档时，建议保持默认。

### 调整分卷大小

```powershell
.\run.bat archive --until latest --target-volume-mib 40 --max-volume-mib 50
```

- 默认 45 MiB 是新开下一卷的目标线。
- 默认 50 MiB（52,428,800 字节）是硬上限。
- 旧卷低于目标线时会尝试加入新增动态；若连下一条完整动态都放不下，会直接新开一卷。
- 单条动态本身超过硬上限时，只能让它单独成为超限卷，并在清单中标记 `oversize`。
- 首次建立归档后，大小策略写入状态文件；后续以状态记录为准，避免同一套归档中途改变规则。

### 自定义输出和状态文件

```powershell
.\run.bat archive `
  --until latest `
  --output-root "D:\朋友圈归档" `
  --state "D:\朋友圈归档状态\archive_state.json"
```

一个状态文件只能绑定一个微信账号和一个输出目录。多个账号或多套独立归档必须分别指定 `--state` 与 `--output-root`。

## 输出文件和 PDF 细节

默认正式文件位于 `output/archive/`：

| 文件 | 作用 |
| --- | --- |
| `微信朋友圈正式备份_第001卷.pdf` | 正式 PDF；之后按 002、003……编号 |
| `archive_manifest.json` | 整套归档的卷清单、首尾日期、条数、页数、大小和 SHA-256 |
| `archive_report.json` | 最近一次运行的缓存范围、截止参数、新增数和变更卷 |

断点位于 `runtime/archive_state.json`，包含动态去重哈希和每卷清单。它不保存动态正文，但它是安全增量的依据：

- 不要手工编辑、移动或删除状态文件。
- 不要修改已经由归档命令管理的 PDF。
- 建议把 PDF、`archive_manifest.json` 和状态文件一起备份。
- 如果正式替换前进程异常退出，下次运行会根据新旧 SHA-256 自动完成或撤销未完成事务。
- 如果 PDF 丢失、被外部软件改写或哈希不符，工具会停止，不会盲目继续追加。
- 如果后来才发现一条早于当前断点的历史动态，工具会停止并报告最早时间，不会把旧记录错误追加到末尾。为保持严格时间顺序，应使用新的空输出目录和状态文件重建。

每个 PDF 都内嵌归档元数据，包括动态数、首尾时间和动态 ID 清单摘要。生成后工具会重新打开全部页面，核对这些元数据，并渲染首尾页面检查是否疑似空白。PDF 是重新构建并合法合并的，不是把二进制字节直接拼到旧文件尾部。

达到分卷线后，旧卷不再改写；只有当前活动卷可能在加入新增动态时被原子替换。这既减少重复工作，也让已经封卷的文件哈希保持稳定。

## 一次滚动大约能加载多少条

微信没有公开固定分页条数。下列只是经验估算，会受微信版本、网络、图片数量、电脑性能和发帖密度影响：

- 一次触底并等待：常见约 10～30 条。
- 连续滚动约 1 分钟：常见约 50～150 条。
- 连续滚动几分钟：可能约 100～300 条以上。

工具内部数据库查询每页最多读取 200 条，这与微信界面一次滚动加载多少条不是同一个概念。是否缓存成功应以 `archive --dry-run` 输出的缓存范围和新增条数为准，而不是只看滚动时间。

## 限制和安全边界

- **仅 Windows**：macOS/Linux 不正式支持，不提供绕过系统保护提取密钥的教程。
- **不会自动滚动**：用户必须在微信界面中加载目标历史。自动控制 UI 容易随微信版本、缩放和风控变化，未纳入正式归档链路。
- **缓存不等于服务器完整历史**：没在这台电脑上加载过、已删除、仅自己可见但未落盘或被微信清理的内容，工具无法凭空恢复。
- **互动可能不完整**：列表页未缓存评论时，需要打开详情；工具不会远程补取历史评论。
- **清晰度受缓存限制**：排版保证完整不裁切，但不能把低清缓存变成原图。
- **视频只留封面**：不导出可播放视频本体。
- **锁定单任务**：同一状态文件不能同时运行两个归档进程。
- **不要共享密钥**：数据库密钥、图片密钥和带签名的媒体 URL 都属于敏感信息。
- **微信升级风险**：微信本地数据库结构变化后可能需要更新解析器。未知版本应先用 `--dry-run` 和小日期范围验证。

## 普通导出模式

除正式增量归档外，原来的交互式 Markdown / HTML / PDF 导出仍然保留：

```powershell
.\run.bat
```

也可以固定参数运行一次普通范围导出：

```powershell
.\run.bat `
  --start "2022-01-01" `
  --end "2022-12-31" `
  --only-self y `
  --keep-interactions y `
  --order oldest `
  --no-download
```

普通模式每次创建 `output/YYYYMMDD_HHMMSS/`，里面有 `moments.pdf`、`moments.html`、`moments.md`、`figure/`、`coverage.json` 和 `params.json`。它适合试导、检查 HTML 或做一次性范围导出；长期备份请使用 `archive`。

已有的手工 PDF 不能仅凭日期安全接管成归档状态，因为 PDF 中通常没有原始动态 ID。新工具发现输出目录已有正式卷但没有状态文件时会停止，避免误覆盖。最稳妥的方式是在新的空目录建立一次工具管理的归档。

## 配置

首次运行会把 `config/config.example.json` 复制为本机专用的 `config/config.json`。通常无需修改。自动定位失败时，可以填写微信数据根目录：

```json
{
  "db_key": "",
  "wechat_data_root": "D:\\WeChatData\\xwechat_files\\wxid_example_ab12",
  "account": "",
  "self_username": "",
  "self_display_name": "",
  "output_root": ""
}
```

`wechat_data_root` 可以指向微信数据根目录、账号目录或包含 `db_storage` 的目录。不要把自动取得的 64 位十六进制 `db_key` 写进公开仓库。

## 常见问题

### 找不到朋友圈数据库

确认 Windows 版微信登录过该账号，并在朋友圈中实际滚动过。若微信文件保存在非默认位置，在微信“设置 → 文件管理”中打开文件夹，把路径填写到 `wechat_data_root`。

### 新增条数是 0

通常表示微信尚未把新一段历史写入本地、指定的 `--until` 早于断点，或者这些动态已经归档。回到微信继续滚动，等待几秒后先运行 `--dry-run`。

### 评论没有导出

使用默认的 `--keep-interactions y`，并在微信中打开相应动态详情让评论落入缓存。之后新增动态会带上可读到的互动；已归档页面不会被自动回溯重写。

### 图片仍然模糊

工具会优先找本机已有的较清晰缓存，但无法制造不存在的原图。可以在微信里点开原图或大图，返回后对尚未归档的动态再运行。PDF 排版会完整显示缓存图，不会用半张占位。

### 依赖安装失败

确认 Python 为 3.10+ 64 位，并查看 `runtime/install.log`。仓库 wheel 不匹配当前 Python 时需要联网从 PyPI 安装。公司网络、代理或杀毒软件也可能阻止安装或进程读取。

### PDF 被修改或状态丢失

从同一次备份中同时恢复 PDF、`archive_manifest.json` 和 `runtime/archive_state.json`。不要创建一个空状态去强行接管已有 PDF。

## 是否需要 AI

正常使用不需要豆包、DeepSeek、Codex 或其他 AI。普通用户只需完成三件事：

1. 在 Windows 微信中从最早日期向后滚动并记住截止日。
2. 运行 `run.bat archive --until 截止日`。
3. 检查输出目录和报告。

AI 或开发人员只在微信新版兼容、异常数据库、缺失依赖或需要二次开发时有帮助。纯网页聊天型 AI 无法访问本机微信数据，也不能代替执行工具。

## 开发与验证

关键文件：

- `src/wxmoments.py`：数据库、SNS、媒体、互动及单次 PDF 导出核心。
- `src/wxmoments_archive.py`：断点、动态 ID 去重、自动分卷、事务、清单和 PDF 校验。
- `src/wxmoments_cli.py`：兼容普通模式并路由 `archive` 子命令。
- `run.bat`：Windows 环境与依赖启动入口。
- `tests/`：位置、完整比例图片、视频封面、分页去重和归档事务测试。

运行测试：

```powershell
.\runtime\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

当前归档命令已经覆盖普通用户的标准增量 PDF 工作流。尚未包含桌面 GUI、微信自动滚动、可播放视频归档、已有任意 PDF 的无损接管和正式签名安装包；这些属于后续产品化功能，不影响命令行归档的正常使用。
